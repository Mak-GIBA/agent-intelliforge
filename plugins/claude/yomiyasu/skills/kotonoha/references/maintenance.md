# 上流更新の保守

上流更新を明示的に依頼された場合だけ読む。通常の執筆では通信・導入・更新を行わない。

リポジトリの`tools/codex-yomiyasu/update_upstreams.py`で`check → prepare → verify → promote`を行う。対象は`--source yomiyasu|meiseki|all`、候補の保存先は`--candidate DIR`。個別対象には`--ref TAG`で安定リリースを固定できる。

prepareは候補の原典と内部アダプターを別ディレクトリへ固定する。原典の取得は統合完了を意味しない。差分を全文確認し、執筆・推敲に必要な規則・検査ロジック・依存の変更を候補へ反映する。理解度クイズ・自動フックなど対象外の機能は理由を記録する。

能力対応表で既存能力の欠落と新規機能の未反映を調べる。verifyはオフライン検査と、別途実行した文章品質比較の記録を照合する。重大な意味変更、品質低下、未検証は採用保留。promoteは一致する検証記録がある候補だけを正本へ反映し、元の導入先は変更しない。

GitHub API制限・通信障害・未知の構造・依存不整合では現在の採用版を保持する。署名や人の承認をハッシュ一致から推測しない。原典、内部規則、検査器と検証の組合せをまとめて管理する。

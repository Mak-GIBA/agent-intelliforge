# 原形を試してから適応・改変する

新規のoriginal_first_contract_version=1に適用する。保存済みrunの工程・評価条件・証拠は移行しない。
対象課題の共通入力で原形を試す。論文の公開スコアの完全再現は、依頼・予算上必要な場合に行う。

## 原典確認と最初の比較

候補探索→有望候補の原典確認→隔離環境の準備→評価条件の固定→原形の実行→結果の独立確認→必要な改変→再比較の順に進む。
有望な論文の本文・必要な補遺、公式OSSの実装・使用例・設定・テスト・利用条件を実験設計前に確認する。
初期候補は既存の基準案と有望な既存方式を中心にする。約5候補という目安を、4個の独自案を先に作る指示へ読み替えない。
公式OSSが使えるなら公開API・公式の実行経路をまず使う。公式実装がなければ原手法の機構を保つ再実装を検討する。
設定が不明、必要機能がない、環境を作れない場合は未検証とする。簡略な独自PoCへ置換して原手法の成績を測ったことにしない。
文献・設計調査は原典に基づく比較で完了できる。効果の実測を求められた研究を文献調査へ下げない。

候補のsource_reviewにimplementationを加える。

```json
{"kind":"official_adapter","source_ids":["REPO1"],"version":"実際の固定tag/commit",
 "method":"原手法で維持する処理","differences":["モデル接続だけを既存の接続へ変更"],"parent_id":""}
```

kindはbuiltin（既存の基準案）、official（公式実装）、official_adapter（接続・入出力の調整）、faithful（原手法の再実装）、adapted（改変）、approximation（近似）。
公式版と同じ機構か、論文と同じ実験条件かは別に記録する。モデルを置き換えた比較を論文の公開成績の再現としない。

## 隔離した準備とモデル接続

依存は候補別の研究専用環境へ導入する。パッケージ版・repositoryのcommitを固定し、親が実行結果を保存する。
Pythonは取得したwheelのハッシュと実際の導入一覧、Nodeはpackage-lockのハッシュを残す。
中断して結果が未確定の準備は自動再実行せず、既存ファイルと記録を確認できるように保持する。
アプリやグローバル環境への導入、OS設定の変更、無断の大容量モデル・データ取得は行わない。
`--allow-network`は原典・依存取得の許可。実験用モデルアクセスは別に`--allow-model-access --model-call-limit N`で範囲を固定する。
必要なモデル呼び出しは親のbridgeを使い、認証情報を実験コードへ渡さない。OPENAI_BASE_URL/OPENAI_API_KEYは親bridgeの一時接続情報になる。
モデル本体の実接続には設定済みAPIかログイン済みCodex CLIを使う。新しいログイン、APIキー取得、設定変更を自動で行わない。
明示接続は`--model-connection <既存JSON>`。APIのキーはkey_envで指定し、秘密値をJSONへ書かない。

```json
{"backend":"api","base_url":"https://provider.example/v1","key_env":"RESEARCH_API_KEY",
 "model":"設定済みのモデル","capabilities":["text","json"]}
```

未指定なら設定済みのAPI接続を検討し、必要な機能を満たさなければログイン済みCLIを検討する。接続確認は合成入力で行い、評価データを計画固定前に使わない。
全候補で実際のモデル・接続・設定をそろえ、比較開始後に一部の候補だけを切り替えない。CLIはagent wrapperであり、通常のAPIと同等とは扱わない。
CLIで保証できないsampling設定、native tool calling、未対応の画像等が必要なら実行を保留する。機構を勝手に簡略化しない。
取得できた使用量のみを記録し、欠測を0や請求額の推定で補わない。接続確認・失敗も実験用モデルの呼び出し上限へ含める。
公式のCLI認証・構造化出力仕様: [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)。CLIのログイン情報をAPIキーへ変換・抽出しない。

## 原形の結果から変更する

原形で要件を満たすなら、そのまま採用候補にする。独自性や工程数を増やすことを目的にしない。
変更は、実測で確認した不足と実行記録を根拠に行う。環境不足・接続不能は手法の性能不良ではない。
改変候補には新しいID、測定済みのparent_id、変更点を記録する。元の評価条件と結果は保持したまま、別の比較契約を固定する。
共通の入力・期待結果・指標・対照条件・モデルは変えない。基準案の実測をDR_ORIGINAL_RESULTSから読み、元のtrial行を変更せず再利用する。
DR_RUNTIMESの候補別python/node_modules/repository配置を使い、実験コードが依存を導入しない。改変段階では変更した候補だけを実行する。
親が元のtrialとの一致を確認する。元の出力を正解ラベルから作り直したり、再利用した結果を新たな実行回数へ足したりしない。
準備・モデル接続・原形・改変は共有の時間枠で実行し、1反復あたり最大3実験の枠を工程ごとに増やさない。
独立レビューが未解決なら実測を残して停止する。再開では完了済み実行を再利用し、元の科学的記録を書き換えない。

## 報告

原形の由来・版、維持した機構と接続上の差、実際の入力と結果、変更が必要だった理由、改変前後の差、未検証範囲を説明する。
図では原形・接続アダプター・変更部分を区別する。近似版の結果から公式実装や論文の手法一般を否定しない。

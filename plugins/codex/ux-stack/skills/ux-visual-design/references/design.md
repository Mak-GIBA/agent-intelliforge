# UI設計と引き継ぎ

対象・操作・状態を決めた後、既存の部品・変数・レイアウト規則を調べる。
主な対象と次の操作が分かる情報階層を作り、密度、文字、色、余白、整列、CTAの優先順位を揃える。
フォームではラベル、入力例、エラーと対象欄の対応、入力保持、取消後の戻り先を設計する。

新規・大幅変更で有益なら複数案を作り、目的達成までの経路、情報の発見、判断や再入力、
状態の見失いやすさ、必要な機能、表示品質で長所・短所を比べる。装飾の量や流行だけで採用しない。
軽微な変更で案の作り直しを要求しない。

Desktop、Tablet、Mobileで情報の優先順位と機能を維持する。重要な入口を隠すことで簡潔さを作らない。
キーボード、フォーカス、ラベルと読み上げ名、コントラスト、エラー・処理中・空・成功の表示を確認する。
見えない操作を欠落と断定せず、実操作で位置と結果を確かめる。

引き継ぎには契約の版、画面・操作ID、外部ID、使用する部品・変数、レスポンシブと状態、
受け入れ条件、未決事項を含める。FigmaのUI取り込みが編集可能なlayersであっても、既存部品との結び付きまで
維持されるとは仮定しない。実装からdesignへ戻すときも部品と状態の対応を確認する。

実装後は同じ経路を画像と操作で確認する。UI自動評価を人間のユーザビリティテストや承認と混同しない。

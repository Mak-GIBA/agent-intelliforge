# v0.1.0：Codex中心の配布整備とWindows・Claude Code試験対応

Agent Intelliforgeに、導入内容を確認してから実行できる共通CLIと、標準Pythonパッケージによる配布経路を追加しました。Codexを引き続き既定の対象とし、Windowsのネイティブ導入とClaude Code向けPluginを選べる構成にしています。Windows・Claudeの追加経路は、実機と実モデルでの検証が残るため試験対応として提供します。

## 導入内容の確認とソースの編集

各キットの`tools/<kit>/kit.json`に、Skill、取得元、依存ソフト、配置先、設定の変更範囲をまとめました。`intelliforge inspect`で実行予定を確認でき、一括スクリプトの冒頭にも同じ定義から生成した案内を載せています。`--apply`を付けない導入・更新・解除は予定を表示するだけで、ホストのPlugin管理CLIやネットワーク取得を実行しません。

GitHub管理、Office、Herdrでは、従来の単一ファイルに埋め込まれていた資材を、編集できるソースと配布用の生成処理に分けました。元の形式を再生成する検査を用意し、今回の構造変更で従来の配布ファイルの実行内容が変わっていないことを照合しています。既存のキットの規範・検査・ハーネスを再利用し、OSとホストに依存する部分を追加配布用のコピーで接続します。

## 共通CLIとホスト別の導入

共通CLIはPython 3.11以上に対応し、wheelとsdistを構築できます。uvのツール環境、pipx、独立したvenvで導入できる標準のconsole entry pointを提供します。PyPIへの公開は行っていません。

リポジトリから導入する場合は、選んだホストの公式CLIと認証を用意したうえで、次を実行してください。

```bash
git clone https://github.com/Mak-GIBA/agent-intelliforge.git
cd agent-intelliforge
uv tool install .
intelliforge list
intelliforge inspect --only yomiyasu --json

# Linux / WSL2：従来のCodex方式
intelliforge install --only yomiyasu --apply

# CodexのPlugin方式を選択
intelliforge install --agent codex --plugin --only yomiyasu --apply

# Claude Codeの試験対応
intelliforge install --agent claude --only yomiyasu --apply
```

配布wheelをダウンロードした場合は、`uv tool install ./agent_intelliforge-0.1.0-py3-none-any.whl`で共通CLIを導入できます。パッケージの構築・導入だけでは、Skillやホスト設定を更新しません。

Windowsでも同じ`intelliforge`コマンドを使えます。checkoutから実行するPowerShell入口も追加しました。

```powershell
git clone --config core.longpaths=true https://github.com/Mak-GIBA/agent-intelliforge.git
cd agent-intelliforge
uv tool install .
.\install_all.ps1 --only yomiyasu
.\install_all.ps1 --only yomiyasu --apply
```

既存の研究資料には長いパスが含まれるため、Windowsのcloneでは`core.longpaths`を新しく作るリポジトリに設定します。資料の配置とGitのグローバル設定は維持します。

Windowsの追加経路はBash・WSL・Dockerを前提にしません。日本語資材はUTF-8で扱い、プロセスの出力上限、タイムアウト、Job Objectによる子プロセス回収を実装しています。ClaudeのWindows実験では公式PowerShellツールを子プロセス内で有効にし、利用者のシェル設定には書き込みません。

## 互換性と更新時の保護

Linux / WSL2でホストや配布方式を指定しなければ、共通CLIは従来の`install_all.sh`と個別インストーラーへ委譲します。従来の単一ファイル配布、キット名、既定値、管理方式を継続します。元のインストーラーとのファイルハッシュ比較では、一括入口に追加した説明コメントを除き、実行内容が一致しています。

追加経路ではCodexとClaudeの管理資材を分け、Plugin登録を各ホストの公式管理CLIへ委ねます。未管理のSkill、既存のWorkgraphフック、手動編集、リンク・junction、衝突する配置先を自動で移行・上書きしません。管理資材は所有権とハッシュを確認し、ステージング・バックアップを経て更新します。Plugin登録に失敗した場合は管理資材を戻し、ホスト側の状態はそのホストの管理CLIで確認します。

yomiyasuの上流原本と独自規範は分離したまま保持します。上流のみの更新、`auto / explicit`の切替、診断、解除に対応し、独自規範を上流更新で置き換えません。共通CLIの配布バージョン、各キットのバージョン、上流資材のバージョンは別に管理します。

```bash
intelliforge update --agent claude --only yomiyasu --upstream-only --apply
intelliforge update --agent claude --only yomiyasu --mode explicit --apply
intelliforge doctor --agent claude --only yomiyasu
intelliforge uninstall --agent claude --only yomiyasu --apply
```

解除は管理するPluginまたはSkillを対象とし、Memoryのノートや研究成果物、バックアップ、上流原本、依存環境を残します。

## 確認した範囲

Linuxで既存試験と追加経路の契約試験を実行し、一時ホーム・一時設定・一時Skillディレクトリから配布パッケージを確認しました。Codex CLI 0.162.1では、yomiyasuの実Plugin導入、再実行、モード切替、通常更新、上流のみの更新、診断、解除と、検証済み上流scriptの呼び出しが成功しています。Codexの隔離試験では、一時fixtureの読み取り成功と書き込み拒否を確認しました。

生成物とソースのハッシュ照合、従来インストーラーの再生成検査、Bash構文検査、yomiyasuの自己テスト、wheel・sdistの構築も実施しています。個別の件数と検証条件は[検証結果](../cross-platform-validation.md)に記録しています。

## 試験対応の範囲

Windows 11の実導入、ProcessContainer、ブラウザー操作、Claudeの認証・実Plugin導入・MXCでのモデル実行、研究・UX評価の全工程は、今回のLinux検証では確認していません。追加したWindows CIの共通試験も、これらの実機・モデル評価の代わりにはなりません。

Claudeの研究・UX実験はNode.js 24以上と固定版Microsoft MXC SDKを使い、必要な隔離が用意できなければ停止します。製品専用のブラウザーや画像生成機能をClaudeで利用できるとは扱わず、UXには同梱のローカルPlaywright経路を接続します。Officeの完全な描画、Docling、任意MCP、HerdrのWindowsセッション操作も別途確認が必要です。

導入先や必要な外部ソフトはキットごとに異なります。既存環境を使っている場合は、導入前に`inspect`と[導入ガイド](../cross-platform.md)で選ぶ経路と競合条件を確認してください。

# yomiyasuと補助Skillで日本語の構成と表現を整える

[docs一覧](../README.md) · [導入手順](installation.md) · [使い方](usage.md)

日本語の技術文書、仕様書、Issue・PR、報告文などを、意味を保ったまま読みやすく整えるためのSkillです。
主張、数値、専門用語、条件、断定の強さを確認し、読みにくい表現を直し、重要な主張から仕組みや実際の変化を追える文章を目指します。
2.0.0-proposal.3では、通常の執筆・推敲をyomiyasu一つから進めます。複数段落の構成ではparagraph-writing、留保の点検ではjapanese-direct-writingの実際のSKILL.mdを読んで適用します。同じ下書きを使い、提出前に読者の立場で一度点検します。必要な条件や不確実性は保持します。
重要な主張の説明が不足する場合だけ、主張・説明・具体化・帰結の足りない役割を補います。4文の型や必須の具体例にはせず、短い連絡や十分な原稿には説明を増やしません。
補助スキルは、段落構成だけ、留保だけを直す部分作業の入口としても使えます。局所的な誤字修正には全工程を加えず、同じ文章を複数のスキルで別々に書き直すことも避けます。

[install_codex_yomiyasu.sh](../../install_codex_yomiyasu.sh)は単体で使えます。
引数なしでは導入予定を表示し、`--apply`で配置します。

## 導入するもの

| 資材 | 提供元 | 役割 |
|---|---|---|
| yomiyasuの原本・lint・diff | [nanaism/yomiyasu](https://github.com/nanaism/yomiyasu) | 日本語の推敲手順と静的検査 |
| Codex用の入口と運用設定 | このリポジトリ | 読者、段落、表現、留保を一続きで点検し、意味と事実を保持する |
| paragraph-writing | このリポジトリ。Gistに由来する旧版から役割を限定 | 段落構成の単独依頼とyomiyasuの構成工程で使う |
| japanese-direct-writing | 提供されたZIPに由来する旧版から役割を限定 | 留保の単独依頼とyomiyasuの点検工程で使う |
| `scripts/check.py` | このリポジトリ | 読者に不要な制作説明、段落の冒頭、数値・コード等の変化を調べ、原本の検査も実行する |

yomiyasuの上流原本は`upstream/SKILL.upstream.md`と参照資料・検査スクリプト・ライセンスを含めて保存します。補助スキルの現在の本文はこのリポジトリで管理し、由来と変更の扱いを`UPSTREAM.json`・`SOURCE.json`に記録します。1.3.0のZIP原本そのものを配置する方式から変わっています。
補助スキルは同梱版から導入・更新し、GistやZIPの元の保存先へはアクセスしません。
ECC、Basic Memory、Office Workbench、GitHub Project Directorは必須の依存ではありません。
既存のHook、MCP、AGENTS、他のSkillの設定は変更しません。

## 読む順序

1. [導入手順](installation.md)で配置先と更新方法を確認します。
2. [使い方](usage.md)で対象の文章と保持する条件を指定します。

このリポジトリの追加設定は、上流の校正手順をCodexで使うためのものです。
文章への効果と具体例は[比較検証](validation.md)に記載します。過去の3案比較ではC案の連携を確認しました。今回の説明の深さの新旧66稿を別に比較し、改善例と説明不足・反復の残存を記録しました。最初の48稿では主指標の改善を確認できず、追試18稿も少数の自動評価なので一般的な品質優位性は未確認です。設計と一次資料の採否は[説明の設計](explanation-design.md)を参照してください。インストーラーの自己テストと文章品質の評価は別です。

# 旧版の推敲フローを保つ単一Skill

kotonoha 4.1.0は、3.0.0の工程と詳細規則を、一つのフォルダへ移した構成です。基本工程を短い箇条書きへ置き換えた4.0.0から、元の参照条件と具体例を戻しています。通常の作業では`$kotonoha`だけを入口に使います。

## 維持する工程と参照条件

| 工程 | 参照する内容 | 条件 |
|---|---|---|
| 読者・作業範囲・保護事項 | audience | 基本の推敲で読む |
| 下書きと明晰化 | clarity | 基本の推敲で読む。否定・条件から先に点検 |
| 段落設計・構成 | paragraphs | 複数段落を設計・再構成するとき |
| 説明の深さ | explanation | 重要な主張から理由・処理・差異を追えないとき |
| 留保整理 | directness | 留保を扱うとき |
| 自然さ | finish | 明晰化した同じ下書きに適用 |
| 読者レビュー | review | 通読し、必要箇所だけ最大一回改稿 |
| ファイル検査 | file-reviewと検査器 | ファイル推敲の編集前後 |

診断では書き換えず、部分修正は指定範囲へ収めます。段落数・文数・PREP・指摘ゼロを目的にしません。一つの下書きを引き継ぎ、同じ資料の再読や工程ごとの全文再生成は増やしません。

## 旧資料との対応

| 旧3.0.0 | 単一Skill内の配置 |
|---|---|
| 旧入口の目的・意味保持・完成稿出力などの宣言 | 工程本体と明晰化・仕上げ・説明・レビューの規則へ集約 |
| 隣接yomiyasuの共通フロー | SKILL.mdの工程本体 |
| audience・clarity・explanation・finish・review | 同名の内部参照資料。規範本文を保持 |
| paragraph-writingの本文 | paragraphs。独立Skill用の配線だけ整理 |
| japanese-direct-writingの本文 | directness。具体例と例外も保持 |
| naturalness | 表現判断が必要な場合の追加資料として保持 |
| paragraphs・directnessの代替コピー | 詳細版と重複するため一本化 |
| reader-reviewの転送 | 正本reviewを直接参照 |

移植元はGitの`6da3e4`です。このPCの3.0.0の入口と主要資料が同じ内容であることも確認しています。配布する`FLOW.json`は、移植元のhash、相対参照などの許可した置換、移植先の保持部分、必須資料と条件付き資料を記録します。オフライン検査では元の本文を復元して照合し、具体例の削除や条件の変更、リンク切れを検出します。

## meiseki・yomiyasuの詳細

明晰化の資料で判断できない場合は、meisekiのpatternsから該当カテゴリへ進みます。否定・条件、修飾・係り受け、名詞化などの入口を示し、全カテゴリの読込は強制しません。

自然さの資料で判断できない場合は、表現の資料、またはメール・研究報告・提案・手順書などの該当資料へ進みます。原版Skill本文も出典として保持しますが、調整済みフローを優先し、外部送信、hook、独自の採点や提出書式を通常工程へ持ち込みません。

固定上流はyomiyasu v2.4.0とmeiseki v0.10.0です。旧3.0.0の実動作比較では旧版の資材も固定するため、原典の版の違いは記録して比較します。

## 確認する性質

規範本文の保持、必要資料の実読込、検査器の実行、入力とSkillの保持、完成稿の意味・構成・自然さを確認します。資料の読込から内部の適用回数は推測しません。最終稿を試験の外で修正して合格にせず、規範を変更した場合はそのSkillを再実行します。

実試験で見つかった誤読に対応し、保持部分の外へ否定の量化、比較関係、説明の重複、元の見出し構造、重要性の主張、診断の見出し点検を補足しました。工程や原規範を短い要約へ置き換える変更はしていません。

4.0.0の一括入力による18課題比較は履歴として残します。今回の参照経路や規範の品質証拠には流用しません。実測条件・結果・限界は[検証結果](validation.md)へ記録します。

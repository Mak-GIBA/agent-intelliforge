# 説明の深さを加える設計

## 現行版でできることと不足

作業開始時の2.0.0-proposal.2を[固定した原稿](../../tools/codex-yomiyasu/evaluation-explanation/snapshots/baseline/assets/)として保持した。既存の段落規範は、主題、根拠、その解釈をつなぎ、意味保持と読者境界の保護が詳しい。paragraph-writingとjapanese-direct-writingの実ファイルを読む工程も既にある。追加Skillで同じ機能を重ねる必要はない。

不足するのは、根拠の対応を確認した後に「処理がどう変わるか」まで説明を下ろす判断である。抽象名詞を自然な表現へ直す規範はあるが、読者が仕組み・操作・差異を理解できたかを独立に測る評価は弱かった。既存評価は主に段落、自然さ、読者適合を測っており、完了稿が全て合格した過去の比較から説明の深さの改善は言えない。

入口末尾、review.md、reader-review.mdには意味・読者・段落の点検が重複していた。今回はその点検をreview.mdへ統合し、古いreader-review.mdは参照先だけ残す。数値、否定、比較条件、因果、主体、確信度、制作説明の除去は新レビューにも維持する。改稿は問題箇所の一回とし、自己採点の反復は増やさない。

## 小さく追加する構造

yomiyasuを入口に保ち、explanation.mdを必要時だけ読む。主張・説明・具体化・帰結は文の役割であり、4文のテンプレートではない。段落資料に短い参照を置き、最終レビューへ読者の疑問を組み込む。補助2Skillの本文と発動範囲は今回変更しない。

推敲は素材にある処理の展開と許された推論に限る。新規解説の仮想例は実測と区別する。未調査の原因を創作せず、必要な条件を残す。接続詞は論理関係で選び、回数を目標にしない。文が読者の疑問に答えなければ加えない。

check.pyには抽象語や接続詞による品質判定を追加しない。「重要」や「具体的には」は適切な文にも現れ、含まれなくても説明不足は起こる。この変更には誤検知・見逃しを上回る静的判定の根拠がない。既存の候補提示、outline、意味保持の照合を使い、説明の深さは本文のレビューと実生成で測る。

上流原本のコード・本文、導入・所有権・ハッシュ・バックアップ・ロールバックの処理は変更しない。独自版proposal.3と上流版v1.1.1は別に管理する。上流だけの更新では新参照を含む独自資材がバイト単位で保持されることを移行テストで確認する。実PCの導入資材を検証用に更新しない。

## 実測を受けた小さな調整

最初の48稿では説明の深さの差が−0.0185点で、事前の改善目安には届かなかった。特に研究手法の評価項目を定義しても、なぜ分けるかが伝わらない例が両版に残った。規範を長く積み上げる理由は得られず、手順の再述と理由の説明を区別する短い補足だけを追加した。初期案の原文・採点を保持し、未使用6課題で旧版・初期案・調整版を各1回比較する。詳細と限界は[実測結果](explanation-results.md)に記載する。

## 分かる説明へ展開できた例

E02の原稿：

> キャッシュの活用は応答の効率化に寄与する。ただし更新管理も重要である。

補足資料には、応答の再利用、キャッシュヒット、期限切れの再取得がある。初期改善案の実出力は次の通り。

> キャッシュは、サーバーから取得した応答を保存し、再利用する仕組みである。保存した応答を再利用できる場合を「キャッシュヒット」と呼ぶ。キャッシュヒットでは、同じ応答をサーバーから取得し直す処理を省ける。
>
> ただし、情報が更新された後も古い応答を使うと、画面の情報が古いままになる。そのため、保存した応答をいつ取得し直すかの管理も重要である。ここで扱う方式では、保存した応答に有効期限を設け、期限が切れた場合にサーバーから取得し直す。

「効率化」を、保存した応答の再利用と再取得の省略へ展開した。「更新管理」は、古い表示が残る条件と、期限切れの再取得へつながっている。性能値を作らず、説明に必要な専門用語を定義した。旧版もこの課題では十分な説明ができており、この例だけで新版の優位性を主張しない。

E09の初期案は、抽象的な重要性と「具体的には」の反復を次の2段落に置き換えた。

> 変更履歴には変更前の内容と日時を残す。誤った変更をした場合は、履歴に残した変更前の内容を復元する。
>
> 変更できる人は管理者に限り、閲覧できる人とは区別する。ただし、こうした管理は事故防止を保証するものではない。

記録・復元・変更権限という動作を示し、接続詞を足さずにつなげた。情報の裏付けは提供資料であり、新しい事故防止の実績は追加していない。

## 残った失敗と調整

E04では、事実保持と読みやすさの定義を説明しても、「この2つを別々に評価します」で止まり、なぜ分けるかが伝わらない稿が両版に残った。初期案の2稿は因果の明瞭さ2点、読者理解3点だった。手順や定義を言い換えるだけでは理由の説明にならない。

E10の初期案には「検索が差の原因と結論づけられない」と「原因かは確認していない」を重ねる稿があり、情報効率は3点だった。E12でも処理ごとのメモリ使用量について同じ意味を重ねる例がある。読者の疑問を全部の段落で順番に回答する規則や、例・結論を必須にする規則は追加しない。

調整は説明参照とレビューの短い補足に限定した。評価項目の列挙を理由の説明にせず、どの違いを見落とさず判断できるかを確認する。新規解説の仮想の対照は実績と区別する。最初の条件・48稿・採点を変更せず、別に固定した未使用6課題で旧版・初期案・調整版を各1回比較する。調整後の結果を最初の主指標に混ぜない。

「同じ入力条件で方式の違いを見る」という意味を読者が追える。文字サイズ別の仮想例も実測と区別し、評価未実施を保持した。H03では「保存前には確認が必要です」を「保存前には、ファイルに書き込む入力内容を確認してください」とし、操作の対象を示した。どちらも接続詞を機械的に追加する改善ではない。

一方、H02の調整版でも末尾の比較手順の再述があり、情報効率は3点だった。初期案も調整版と同点で、補強した2箇所だけの効果は確認できていない。6課題各1回の探索的な追試を、最初の48稿の主指標や一般的な品質優越の証拠に置き換えない。広い指示を増やす理由は得られず、短い理由確認と既存レビューへの統合を採用した。

## 通常の参照読込

実ファイルを使う3試行も別に実行した。新任担当者向けの技術解説ではyomiyasu、paragraph-writing、japanese-direct-writingと、調整後の説明参照の全文を実際に読んだ。短いメールとコードだけの変更では説明参照を読まず、全3試行で事前の読込条件を満たした。技術解説の説明参照には2件の全読込receiptがあり、適用回数が1回だったという証拠にはしない。

技術解説内の静的compareは終了コード1、`REVIEW_REQUIRED`、`meaning_preservation_verified=false`だった。説明に使った語の追加や上流の語尾候補が提示されており、警告を消して意味保持の成功と扱わない。親は素材と実出力を照合し、要求ごとの読込、起動時の保持、編集後の値、再起動、時間未測定が保たれていることを確認した。[手動照合の記録](evidence/explanation-2026-10-11/native-semantic-review.json)は自動判定と分けて残す。

読込確認はコマンドの成功と返された全文の照合である。名前の言及だけは数えず、内部での適用回数、自動選択の一般的成功率、文章品質の優越は証明しない。3Skillは一時プロジェクトに正式なインストーラーで配置し、実PCの導入を変更していない。

[固定資材・出力・採点](https://github.com/Mak-GIBA/agent-intelliforge/tree/871cb8adf0f7c278d22c72c4fbb21fadc5882f72/tools/codex-yomiyasu/evaluation-explanation)と[比較契約](../../tools/codex-yomiyasu/evals/EXPLANATION_STUDY.md)を保存した。`snapshots/improved`は最初の候補であり、調整後の配布本文と混同しない。匿名対応表は採点後に記録として残すが、採点者へは渡していない。実行環境の私的なパス情報は公開しない。

```bash
python3 -B tools/codex-yomiyasu/evals/verify_explanation.py \
  --out tools/codex-yomiyasu/evaluation-explanation
```

この照合は保存済みの入力・出力・集計・読込証拠を調べるもので、新しい生成やインストールは行わない。インストーラーの自己テスト成功は文章品質へ加点しない。実読者による理解度、他モデル・他ジャンルへの一般化は未検証である。

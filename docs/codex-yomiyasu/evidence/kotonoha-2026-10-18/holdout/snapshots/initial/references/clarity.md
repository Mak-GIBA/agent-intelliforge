# meisekiを基礎にした明晰化

意味を変えず、読者が構文を解きほぐす負担を減らす。優先順位は、否定・条件、係り受け、名詞化、冗長、体裁・反復。問題がある種類だけ点検する。

- 否定・条件は、成立する場合と成立しない場合を原稿と照合する。「増大を招かないとは言えない」は「増えることがある」であり「増えない」ではない。控えめな肯定を断定へ変えない。条件が不明なら推測して畳まない。
- 主語と述語、修飾語と対象を近づけ、詰め込んだ文を分割する。主体を推測して補わない。「入力値を検証してから保存する処理を担当する関数」は「この関数は入力値を検証してから保存する」とできる。
- 動作を名詞の連鎖から取り出す。「再送回数の上限の設定の検討」は「再送回数の上限をどう設定するか検討する」とする。専門用語を文字数だけで言い換えない。
- 定型句は文脈で空虚なものだけ減らす。「重要なのは上限を設けることだ」は、義務や推奨の強さを保って述べ直す。比較や限定を担う「多角的」「原則」まで機械的に消さない。
- 同格の条件や手順が長文に埋もれる場合だけリストへ開く。因果の説明までリストへ分断しない。定義とその説明、新しい帰結・例外は反復ではない。

textlintの文長、漢字、二重否定などの指摘は候補であり誤りの断定ではない。スコア低下・指摘ゼロを目指さない。制御文字・特殊文字は勝手に除かず、失われた文字を推測で復元しない。

必要な例がここで判断できないときだけ `../meiseki-upstream/references/patterns.md` の該当カテゴリを読む。原本の全例やスコア計算を毎回読み込まない。

## 1.2.0の子プロセス・MCP確認（2026-10-19）

追加UX監査で使う子CLIの権限と、MCPサーバーの動作・ツール承認を分けて確認しました。実測したCodex CLIは0.160.1です。新規ロールはworkspace-write、旧runは記録済みの権限を維持し、明示的な変更は完了済みの記録を書き換えず適用します。

MCPへ直接接続するdoctorは成功しましたが、実Codexの最初の呼び出しは「MCP tool call requires approval, but approval policy is never」で拒否されました。専用ブラウザーだけに呼び出し内の承認設定を渡すと、画面表示・情報取得・入力・クリック・サイズ変更が成功し、画像とreceiptを保存できました。サーバーの起動成功だけでは、子CLIからの利用成功までは確認できません。[公式のMCP設定](https://learn.chatgpt.com/docs/extend/mcp)と実際の呼び出し結果を照合しています。

| 確認 | 結果・範囲 |
|---|---|
| リポジトリ全体 | Python 3.11で358件、失敗なし、環境依存の4件スキップ |
| UXの契約試験 | 39件成功。新規の書き込み権限、明示的read-only、旧runの権限変更、監査中の編集検知、認証・承認・モデル混雑時の再試行抑止を確認 |
| MCPの実動作 | doctorが実MCPを初期化し、ツール一覧取得、3操作、5画像・8receiptの保存とハッシュ確認に成功。モデル呼び出しはなし |

| 配布・このPC | UX 1.2.0へ管理対象だけを更新。未導入Plugin・MCPは追加せず、個人config.tomlのハッシュを保持 |

再開試験では参考情報をpartialとして対象レビューへ進みました。レビュー役は17件の証拠を含む構造化出力を返しましたが、coverageのviewportと実画像が一致せず、既存の照合処理で停止しました。監査全体が完了した結果としては扱いません。

実モデルの試行では、MCP操作が成功した後のモデル混雑と、外部参考サイトの読み込みタイムアウトも発生しました。これらをMCP起動失敗やアプリの品質不合格と混同しません。検証用アプリでの動作確認であり、実ユーザーの使いやすさ、任意の外部MCP、Windows・Claudeの実機動作は未検証です。

## 自動チェック

~~~bash
python3 -m unittest discover -s tests -p 'test*ux*.py' -v
bash -n install_codex_ux_stack.sh
bash -n tools/codex-ux-stack/skill/scripts/gan-harness.sh
node --check tools/codex-ux-stack/skill/scripts/visual-browser.cjs
~~~

一時HOME、検証用アプリ、模擬Codexで導入・再実行・単体配布・dry-run・編集保護・設定維持・途中失敗・解除・画像検証・反復・停止・再開を確認します。
1.1.0ではooui-designの標準導入、旧ハーネスからの更新、共通参照資料の一致と欠落検出、
4ロールへの同じ基準の供給、別配置のSkillに依存しない動作、yomiyasuの任意扱いも確認します。
個人のSkillやMCP設定には書き込みません。模擬結果はモデルの判断品質や実ユーザーの使いやすさを証明しません。

実Chromiumの確認は明示して実行します。UX_GAN_RUNTIMEにはnpm lockfileから導入した環境を指定します。

~~~bash
UX_GAN_RUNTIME=/path/to/test-runtime \
PLAYWRIGHT_BROWSERS_PATH=/path/to/test-browsers \
python3 -m unittest discover -s tests -p 'test_ux_gan_browser.py' -v
~~~

ローカルフォームで未入力エラー、保存結果、確認ダイアログのキャンセル・承認、Mobile表示、操作前後の画像・ハッシュ、外部参照の閲覧専用制御を確認します。
文書管理の試作では、Desktopで絞り込みと複数選択から詳細・関連文書へ移り、戻った際の条件・選択・下書きの保持を確認します。
Tabletでは一括操作の取消・完了、Mobileでは結果の表示を確認します。これはブラウザー経路と操作記録の検証です。
環境変数がない通常のテストでは、この実ブラウザー確認だけSKIPします。テスト中に勝手にブラウザーを取得しません。

続いて、本人の連絡先変更について800文字以内で設計判断を回答するケースを、read-onlyで実行しました。

## 配布物の再生成

~~~bash
python3 tools/codex-ux-stack/build_installer.py
~~~

同じ正本からは同じ配布物を生成します。埋め込みZIPにはSHA-256を付け、展開内容と正本の一致をテストします。
固定版の更新は[sources.json](../../tools/codex-ux-stack/sources.json)と[browser/package.json](../../tools/codex-ux-stack/browser/package.json)を編集し、
lockfileを更新してから再生成・検証します。

# Codex UX Stack

[English](../en/codex-ux-stack/README.md) | **日本語**

[docs一覧](../README.md) · [導入手順](installation.md) · [使い方](usage.md) · [検証範囲](validation.md)

通常は共通入口の`$ux`へ、相談・レビュー・再設計・実装・改善を依頼します。
依頼と現状から必要な工程を組み合わせ、専門Skillを使って作業を進めます。
レビューで画面構造や導線に原因があれば、図やワイヤーフレームで再設計案を示します。
提案と実装への反映は区別し、「指摘だけ」「設計まで」「コードを変更しない」等の範囲を守ります。
Whimsical／Figmaは明示選択する任意連携です。未接続でもMermaid・SVG・HTMLで進められます。[設計・共同編集の使い方](visual-design.md)

導入・操作・比較の実測と未検証項目は、[1.4.0の検証報告](verification-1.4.0.md)へ分けています。
共通入口の判断・配布・導入は[1.5.0の確認結果](verification-1.5.0.md)にまとめています。

Webアプリで利用者が扱う対象を起点に、画面と操作を設計するキットです。この考え方をOOUI（オブジェクト指向UI）と呼びます。
たとえば予約管理なら、予約の一覧・詳細と、選んだ予約を変更・取り消す操作を対応付けます。実装後は画像とブラウザー操作から、必要な情報が見つかるか、主要操作を完了できるかを確認します。
導入には[install_codex_ux_stack.sh](../../install_codex_ux_stack.sh)を使います。スクリプト単体で使え、WorkgraphやSpecKitは前提にしません。

新規アプリでは、**OOUI設計 → 導線と画面の可視化 → デザイン・実装 → ブラウザー検証**の順で進めます。
ooui-designで利用者、対象、属性、関係、一覧と詳細、操作、状態保持を整理し、短い設計メモを
Product Design / Build Web Appsへ渡します。画像生成や実装にも必須機能と情報の優先順位を引き継ぎます。

検索、一括操作、対象が固定の操作、意味のあるウィザードは、利用者の目的に応じて使い分けます。
主要な作業を中心に情報と操作を整理し、不要な装飾・説明・常設要素を増やしません。必要な操作まで削ったり、情報を隠して探索や往復を増やしたりしないことも重視します。
設計・レビュー・修正の開始時に、利用可能なBasic Memoryから関連する過去の指摘を検索して読みます。
元の文脈と今回の利用者・目的・制約を照合し、適合するものを設計や確認へ反映します。
今回の問題と解消状態は実画面と操作で確認し、適用したノートと理由を既存の所見に短く残します。
未導入・参照不能・該当なしの場合も作業を続けます。Memoryへの保存や設定変更はこの参照手順に含みません。

日本語のラベルや説明、設計メモ、レビュー・比較・改善レポートの下書きは、
kotonohaで一度推敲することを推奨します。未導入なら利用可能なyomiyasuを使い、両方を重ねて適用しません。主張、数値、条件、確認結果、根拠を保ち、短いラベルは長文化しません。
未導入の場合は[別インストーラー](../kotonoha/installation.md)を利用できます。

[ECCの反復構成](https://github.com/affaan-m/ECC/blob/ef648e01899ba3e8dc6371642deaaf64b4477775/scripts/gan-harness.sh)を参考にした、既存アプリ向けの独自実装です。
モデルの学習ではなく、調査・修正・評価を別のCodex実行に分けます。

利用者は案件の指定を優先し、初見・誤操作・急いでいる・説明を読まない視点も補助に使います。
必要な情報と操作を保ち、情報整理、重複削除、操作の統合、文言の置き換えから改善案を検討します。
修正後は手順、判断する箇所、Mobileの情報量を見直します。指摘には画像、解消した指摘には修正前後の画像を付けます。
類似アプリは原則3候補を探し、公開画面や公式の画像から良い工夫と適用案を比較します。

## 最初の操作

対象アプリのフォルダーでCodexを開き、次のように依頼します。

~~~text
$ux
このアプリを、利用者が扱う対象から設計して実装してください。
必要な導線や画面を可視化し、必須機能と状態保持をブラウザーで確認してください。
~~~

改善案の相談なら、再設計を含む提案まで依頼できます。

~~~text
$ux
このアプリの使いにくさを、実画面と操作からレビューしてください。
必要なら画面構造や導線の再設計案も示してください。実装は変更しないでください。
~~~

修正まで任せる場合は「改善し、実装と再確認まで進めて」と指定します。
専門Skillの直接呼び出しも維持しています。詳しくは[使い方](usage.md)を参照してください。
導入後、対象アプリ・URL・テスト環境を指定してレビューや改善を実行します。
AIによる評価と人間のユーザーテストは別です。[検証範囲と制限](validation.md)

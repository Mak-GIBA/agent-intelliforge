# UX Stack 1.4.0：実装と品質検証

2026-11-02。[概要](README.md) · [導入・認証](installation.md) · [設計と共同編集](visual-design.md)

1.4.0は、既存のOOUIと画像付きUX-GANへ、編集可能な設計とローカルの設計契約を追加した版です。
認知負荷のガイドとProduct Design／Build Web Apps連携を維持しています。
ローカル回帰はすべて通過しましたが、一般的なUX品質の向上は比較から実証できていません。
以下では、導入・契約・通信の確認、合成アプリの操作、AIによる画像評価、実モデルの修正反復を分けます。
人間によるユーザビリティテストは実施していません。

## 実装と判断

| 正本 | 役割と変更 |
|---|---|
| `tools/codex-ux-stack/ux-visual-design/` | 新Skill、契約スキーマ、文書管理の例、設計・MCP・共同編集の参照資料 |
| `ux-visual-design/scripts/ux_contract.py` | グラフ・ID・実装パスの検査、Mermaid／SVG／HTML、三者差分、編集保護 |
| `ux-visual-design/scripts/design_mcp.py` | ネイティブCodexの設定・ツール検出・診断・対象限定の呼び出し |
| `skill/scripts/contract_runtime.py` | 契約と参照PNGを固定し、変更・必要な操作証拠の欠落を検出 |
| `skill/scripts/contract-browser.cjs`、`visual-browser.cjs` | ブラウザーの状態・操作対象・遷移・入力保持を画像付きreceiptへ記録 |
| `skill/scripts/harness.py` | Journey／Screen IDを引き継ぎ、契約の未検証・失敗があるrunを合格にしない |
| `install_ux_stack.py`、`build_installer.py` | 新Skillの標準導入・更新、任意MCP、設定保護、単体配布への同梱 |
| `src/agent_intelliforge/{cli,runtime,ux_port}.py` | 追加配布経路の引数・所有権・ヘルパー実行 |
| `tools/intelliforge/build.py` | Codex／ClaudeとPythonパッケージ用の生成資材 |
| `tools/codex-ux-stack/evals/`、`tests/test*ux*.py` | 比較条件・実操作・独立採点・ライフサイクルの検証 |

外部キャンバスだけを正本にすると、要求やコードとの対応を追えません。ローカルJSONで目的・状態・条件・
実装との対応を残し、外部ファイルとノードはIDで関連付けます。人間の変更はbase・local・remoteの三者比較で取り込みます。
契約に対応しない注釈やスタイルは元ファイルへ残し、再生成で消しません。

MCPは登録と認証を分け、設定APIの版を使って対象キーだけを更新します。既存・無効化・解除済みの設定を保持し、
未導入の外部MCPをupdateで追加しません。Core更新では、新しい標準Skillだけを追加します。
dry-runはネイティブCLIも起動しません。外部一覧の取得失敗は構造化して報告し、ローカルのブラウザーへ進めるようにしました。

## 導入・資材・通信の確認

インストーラーと接続診断は一時HOME・CODEX_HOME・キャッシュで実行しました。
全体回帰は、既存の無視対象キャッシュや未管理資材を壊さないよう、Git管理資材のコピーで実行しています。

| 確認 | 結果 |
|---|---|
| リポジトリ全体 | Git管理対象をコピーした環境で565件成功、失敗・skipなし。実ChromiumとネイティブCodex／ローカルMCPを含む |
| UX関連 | 142件成功。上記全体の一部であり、件数を合算しない |
| Python 3.10 | 契約・共同編集・実ブラウザーの30件成功。全体の検証には3.11を使用 |
| 新規Pythonヘルパー2件 | 行カバレッジ90%（MCP 82%、契約95%）。UI品質・権限・人間の使いやすさの保証ではない |
| 実インストール | 単体スクリプトで導入・更新・任意登録・再実行・doctor・手動編集保護・解除を確認 |
| dry-run | 導入・解除とも、一時HOMEのファイル集合と内容のハッシュを保持 |
| 実インストールの初回 | Plugin一覧取得が45秒でタイムアウト。Core資材を保持し、再実行は成功。原因は特定していない |
| 単体配布・再現性 | 正本との展開一致と再生成一致を確認。生成スクリプトを直接編集していない |
| 追加配布物 | 668ファイルの再生成一致。wheelを一時環境へ導入し、一覧・予定表示・両ヘルパーの4呼び出しが成功 |
| Skill | 形式検査と独立した使用試験が成功。共同編集、分岐、入力保持、競合、未対応の注釈、途中失敗時の復元を確認 |
| 証拠の保護 | 画像の改変、契約・参照PNGの変更、読み取り中の変更、必要なreceiptの欠落を検出 |

独立試験では、選択したJourneyの必須条件だけを照合し、対象外・任意の条件を混ぜないことも確認しました。
合成の承認済み条件では、操作23/23件が確認できても参照画像がなければ未検証です。
これは合成の承認状態を使った検査であり、人間の承認を取得した結果ではありません。

WhimsicalとFigmaは、公式URLへの登録と実Codexからの接続診断を一時設定で実行しました。
両方とも `authentication_required`／`authentication: required` でした。実OAuthログイン、対象ファイルの
読み取り・作成・編集、書き込み権限、Design-to-Code／Code-to-Designは未検証です。
ローカルMCPでの通信成功を、両サービスの実操作成功として扱っていません。

### 操作の結果と評価コードの補正

| ケース | 旧版の固定操作 | 追加版の固定操作 |
|---|---:|---:|
| 文書管理 | 72/72 | 69/72 |
| 設定 | 48/48 | 48/48 |
| LP | 42/42 | 42/42 |
| 申込・模擬決済 | 72/72 | 72/72 |
| 合計 | 234/234 | 231/234 |

この件数は2試行×3画面幅のチェック数で、独立したユーザー数やタスク数ではありません。
追加版の3件は、1試行で保存通知が共通の `#status` に出なかった不一致です。
実画面には入力欄の近くに保存完了表示があり、保存機能そのものの欠落やデータ喪失とは区別します。

評価コードには、決済を350msで判定する、中断を完了済みデータで試す、保存とスクロールの途中を失敗にする問題がありました。
処理中の画像を根拠に補正し、操作を再実行せず、観測する条件だけ最大5秒待つようにしました。
同じ補正を両版・全16成果物へ適用し、初期結果・最初の補正・最終補正を別々に保持しています。
生成物のコードや採用条件を、結果が良くなるように書き換えてはいません。

さらに申込確認の画像で、入口アニメーションの不透明度が途中の状態を確認しました。
DOMとURLの一致だけでは完成時の表示を評価できないため、[静止画の補正条件](../../tools/codex-ux-stack/evals/stable-observation-contract.json)を
再計測前に固定しました。有限アニメーションを最大5秒、スクロール停止を最大2秒待ち、
[Playwrightの静止画オプション](https://playwright.dev/docs/api/class-page#page-screenshot)で撮影時のアニメーションを抑制します。
同じ16成果物と操作を両版に適用します。これはアニメーション自体の品質を測る試験ではありません。

各段階の画像・操作・採点を残し、未完了の動きを含む採点を最終外観の評価と混ぜません。
初期採点8/8件、非同期観測の補正後7/8件が完了し、後者の設定ケース2は180秒で時間切れでした。
生成の追加試行やコード変更は行わず、静止画補正後の独立採点を別に集計します。

### 静止画の独立評価と費用

静止画補正後は8対中6対の採点が完了しました。設定の試行1、申込の試行1は180秒で時間切れとなり、
欠測として残しています。途中の出力で補ったり、補正前の点数を流用したりはしません。

| ケース | 採点できた対 | 旧版の6項目平均 | 追加版の6項目平均 |
|---|---:|---:|---:|
| 文書管理 | 2/2 | 4.00 | 4.00 |
| 設定 | 1/2 | 4.33 | 4.00 |
| LP | 2/2 | 4.08 | 3.83 |
| 申込・模擬決済 | 1/2 | 4.00 | 4.50 |

6項目は視覚品質、情報構造、操作の明確さ、導線の整合、認知負荷、画面幅間の一貫性です。
同じ対の両版だけを集計しています。少数のAIによる画像・操作評価であり、人間のタスク達成時間や
主観的な使いやすさを測った値ではありません。文書の同点、設定・LPの低下、申込1対での上昇を残し、
全体の優位性は主張しません。

生成に使った合計時間は旧版2392.2秒、追加版2400.1秒でした。正常終了は旧版1/8、追加版0/8で、
大半が上限に達しているため、この時間差を速度改善・悪化と解釈しません。
比較、補正後の採点、失敗、局所確認を含むCLI実行の累積は12845.7秒（214.1分）でした。
準備・ブラウザー操作を含む実行時間を計上し、240分の上限を守りました。外部デザインMCPの呼び出しは両版とも0です。
その使用効果・料金は未測定で、モデル提供側の請求額も取得していません。時間を料金へ換算した推定は出しません。

生成直後のHTMLハッシュは記録していません。評価コードはアプリを編集しませんが、段階間の内容一致は
ハッシュで独立に証明できません。最終HTMLのハッシュ、匿名対応表、最終集計は私有の検証記録へ残しました。

### 実モデルによる修正反復

[固定した条件](../../tools/codex-ux-stack/evals/visual-repair-contract.json)で、各版の文書管理と申込の試行1へ
必須ボタンを隠す同じ回帰を入れました。旧版は1.3.0、追加版は契約・証拠保護を修正した `59e4912` です。
初回は親ハーネスに子実行フラグを渡す評価側の誤りで、4件とも約0.06秒でモデル呼び出し前に停止しました。
その記録を残し、実モデルを呼ぶ前の失敗に限定して起動処理を修正しました。

| 版・ケース | 経過秒 | 結果 |
|---|---:|---|
| 旧版・文書 | 665.4 | reviewerが420秒で停止、修正反復0 |
| 追加版・文書 | 810.6 | reviewerが420秒で停止、修正反復0 |
| 旧版・申込 | 796.5 | reviewerが420秒で停止、修正反復0 |
| 追加版・申込 | 421.3 | plannerが420秒で停止、修正反復0 |

同条件比較では両版とも修正の完了0/2件です。工程上限は比較の途中で延長せず、反復の改善は未実証とします。

別の[局所条件](../../tools/codex-ux-stack/evals/local-workflow-contract.json)では、ローカルの2画面試作、Desktop、
推論medium、工程300秒、修正上限1回に範囲を絞りました。比較のmax条件や生成成果物へ結果を転用しません。
文書ケースはreviewerがコードを編集したため、申込ケースは修正後reviewerが過去画像のパスを返したため停止しました。
証拠の保護を緩めず、[読み取り専用での確認条件](../../tools/codex-ux-stack/evals/local-recovery-contract.json)を先に固定し、
文書は元の試作から別試行、申込は検証済み修正を保持して未完了レビューだけ再開しました。
この確認後に修正回数を増やしたり、失敗したモデル試行を繰り返したりはしません。

文書の別試行は665.8秒で修正1回と独立再レビューまで完了し、`passed` になりました。
検索語とメモの入力保持を含む設計契約7/7条件と、別の機能テストが成功しました。
初回の無断編集による停止を成功へ書き換えてはいません。局所的な仕組みの確認であり、
生成比較の時間切れや、全画面・全端末の品質を解消した結果ではありません。

再開した申込は必須往復4/4条件と機能テストに成功しました。ただし独立レビューがダブルクリックによる
不要な往復を発見したため、runは `incomplete` です。新しい画面の同じ位置に生成された「戻る」へ2回目の
クリックが届くことを再現し、HTMLプレビュー生成元を修正しました。実Chromiumの回帰テストは成功しましたが、
その最終修正を含む実モデルの再評価は行っていません。契約の充足とUX全体の合格を分けた結果です。
別の実Chromium試験でも、修正前の二重クリックを再現し、修正後の前進・通常の戻る・Enter／Spaceを確認しました。
この独立試験はDesktopの合成試作であり、Mobile・別ブラウザー・実アプリの完了を認定するものではありません。

## 追加のアクセシビリティ確認

axe-core 4.10.3で、各成果物の3画面幅と主要な入力・詳細・失敗状態を走査しました。
これは事前の6項目の採点とは別の追加診断です。各版60走査のうち、旧版46、追加版60走査で
`color-contrast` の違反を検出しました。有限アニメーションを待つ別の走査でも同じ件数でした。
同じ要素を状態・画面幅ごとに再検査しており、独立した不具合数や人数ではありません。
WCAG全体の適合判定ではありません。画像が整っていることと
アクセシビリティの充足を同一視しません。生成例で実証した不足を受け、通常文字4.5:1等の具体的な測定指針を
Skillへ追加しました。この追記後の生成改善は未測定です。
[Playwrightの公式手順](https://playwright.dev/docs/accessibility-testing)が説明するように、
自動検査は一部の問題を検出するもので、手動確認や支援技術を使う人による評価も必要です。

```bash
python3 -B tools/codex-ux-stack/build_installer.py
UX_NATIVE_MCP_TESTS=1 UX_GAN_RUNTIME=/path/to/pinned-runtime \
  python3 -B -m unittest discover -s tests -p 'test*ux*.py' -v
```

モデルの実行には既存の正規認証と明示した予算が必要です。検証用アプリ、画像、API・モデルのログ、匿名化対応表は
`.artifacts/ux-visual-design/` にGit対象外で保存しています。公開するのは手順・固定条件・集計と制限です。
最終集計は、その中の `comparison/final-summary.json` です。
認証情報や生ログ・テスト生成物はコミットしません。Windows／Claudeの実機、大規模アプリ、人間の認知負荷・満足度、
外部サービスの請求費用は未測定です。

# 対象と操作から画面を作る
依頼、利用者、必須機能、既存仕様・デザインシステムを確認する。
新規作成は対象・属性・関係・操作を短く整理して実装へ渡す。既存改善は先に画面を見て操作し、問題のある対象・状態を特定する。局所修正で全体の設計書や新機能を増やさない。
一覧・詳細・関連移動と、入力・検索・選択の保持を整理する。固定対象の手続きにはタスク起点も使い、必ず一覧と詳細へ分けない。
主要な情報と操作の優先順位を明確にし、不要な装飾・説明・常設要素は追加しない。必要な情報を隠して探索や往復を増やさない。
判断が必要なときだけ references/ooui-modeling.md、references/cognitive-load.md の該当箇所を読む。
実装後は references/quality-gates.md を使い、必須機能、表示、状態、実操作を分けて確認する。短いラベル・ボタンの文字が不自然に折り返されないかも実画面で見る。
画像付き監査・修正反復には ux-gan-harness を使い、設計のみの依頼では起動しない。Product Design / Build Web Appsへ渡す際は対象・必須機能・優先順位・状態を保持する。
Memoryと日本語推敲は references/review-policy.md に従い、既に確認した本文や結果を再利用する。Memory参照不能や未導入の補助スキルで作業を止めず、この作業から導入や設定変更を行わない。
未実装、仮応答、未確認、実操作の成功を区別する。スキルの整備依頼を別アプリの修正許可に読み替えない。

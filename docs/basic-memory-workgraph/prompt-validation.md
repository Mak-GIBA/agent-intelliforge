# メモリーhookのプロンプト短縮と挙動確認

2026年10月29日、直前の未コミット版を比較元としてhookの表示と保存方針を短縮した。固定条件では開始時が約30〜39％、終了時が約23％短くなった。検索・採用判断・根拠確認・保存可否の判断条件を保ち、検索本文を要約・削除していない。

## 変更と測定範囲

開始時は実行プレフィックスとタスクIDを一度だけ表示する。`Helper`と`TASK`は説明用の置換記号であり、別のシェル呼び出しまで変数が残ることを仮定しない。検索結果では内部用の指紋・重複識別情報・空の警告・繰り返しの注意文を表示から除く。本文と適用判断用メタデータ、要確認・取得失敗・検索語不足の区別は保持する。CLIのJSON応答、検索条件、件数・本文上限、一時状態の形式は変更しない。

保存方針は文章自体を圧縮し、もともと操作前の参照が必須だったガイドとの重複を整理した。開始時の短い表示は検索用CLIを指定していない構成でも使う。可搬版では保存方針の参照先を実在する`assets/memory-policy.md`へそろえた。

`tiktoken 0.9.0 / o200k_base`で、環境パスを正規化し、制御値を固定した合成fixtureを計数した。通常ケースは`auto=smart / correction=scoped / case=off / skill=review`で、変更前も短い開始表示を使う`compactContext=true`とした。これは比較用のトークン数であり、実モデルの請求トークン数ではない。比較元と改訂版の指紋・計数値は[固定fixture](../../tests/fixtures/workgraph-prompt-v110.json)にある。

| 開始・候補3件 | 1,058 | 642 | 39.3％ |

開始時30％・終了時40％は目標値だった。該当なしの開始時と終了時は未達である。判断条件を保持し、通常の開始・終了fixtureでは20％以上の削減を回帰検査の下限とした。本文が長い場合、本文を保つため全体に対する削減率は小さくなる。

測定の再実行には、保存した比較元ソースと改訂版を指定する。評価用のtiktokenは製品ランタイムの依存へ追加していない。

```bash
python3 tools/basic-memory-workgraph/evaluation/measure_prompts.py \
  --before "/path/to/before/source" --after tools/basic-memory-workgraph --check
```

## 旧方針との対応

正本は引き続き[memory-policy.md](../../tools/basic-memory-workgraph/memory-policy.md)。表のガイドはいずれも変更前から操作時の参照が必須であり、今回その内容を変更していない。

| 旧方針の要件 | 改訂版での保持先・確認点 |
|---|---|
| 現在の指示優先、曖昧なら保存しない、hookは書き込まない | 冒頭。規模・長さ・キーワードは許可にしない |
| 転用性・有用性・根拠・持続性・追加価値の全5基準 | Admissionの5項目。1回の実検証、一般知識・一時設定の除外も保持 |
| 成功・修正の比較、試験の射程、未知を未知とする | Admission後段。試験成功と承認を分離 |
| 将来の明示的な好み、範囲・例外、技術検証不要 | Admission後段。一度の修正・沈黙は恒久的な好みにしない |
| Rule／Workflow／Validationの保存先と必要項目 | Admission後段。作業日誌・完了報告・生ログ等の自動保存は禁止 |
| 自身の実行経路の振り返り、原因不明と対処の効果の分離 | Review節。障害・原因・対処・根拠・次回適用条件を保持 |
| キーワードなしの候補認識、一度だけ評価 | Review節とStop節。候補は保存許可ではない |
| 目的・読者・出力・制約で検索し、本文・適用範囲を読む | Recall節。類例を全作業の規則に変えない |
| 原文の段階・評価、必要なグラフ探索、未完了・否定例 | Recall節。深さ2〜3、関係だけでは適用しない |
| 取得失敗と該当なし、条件への変換、成果物確認 | Recall節とRECALL.md。機械的な整合性と意味の正しさを分離 |
| `needs_review`の再利用・export制限 | Recall／Adoption節とAUDIT.md。疑わしい根拠を肯定的な先例にしない |
| Correctionのscoped／off、効果不明でも保存可能な条件 | Contextual節とCORRECTIONS.md。依頼と効果を分離し、欠けた事実を創作しない |
| Caseのreusable／progressive／offと別個の保存基準 | Contextual節とCAPTURE.md。通常の完了・テスト成功だけでは保存しない |
| 同じ成果物・目的・同一性、順序、引用、旧形式の保持 | Contextual節とCAPTURE.md。Interactionを正本とし、版を越えて受容を転用しない |
| 採用推定、明示承認、検証を分離 | Adoption節とCAPTURE.md。評価を求めず、行為の対象と根拠を保持 |
| commit／pushの相関、暫定判断、沈黙等の除外 | Adoption節とCAPTURE.md。満足度の数値化は禁止 |
| 修正・撤回時の再評価、反証と過去の観測の保持 | Adoption節とCAPTURE.md。検証だけのCaseは推定を空にする |
| 監査のタイミング、構造確認の限界、誤記と実際の失敗を分離 | Adoption節とAUDIT.md |
| 根拠付き修復、前後・理由・根拠・読み戻し、秘密情報の除去 | Adoption節とAUDIT.md。広範な削除や履歴の黙示的な改変は禁止 |
| 派生先への影響、独立根拠の保持、checkedへ戻す条件 | Adoption節とAUDIT.md。深さ1〜2と構造の再検査を保持 |
| Skillのoff／review／auto、Creator不在時の扱い | Workflow節とSKILL_REVIEW.md。判断のみと登録を区別 |
| Skill化の追加価値、既存Skill優先、判断根拠の保持 | Workflow節とSKILL_REVIEW.md。時間や利用回数だけで再レビューしない |
| staging、実際の検証、登録先、管理manifest、ユーザー編集の保護 | Workflow節とSKILL_REVIEW.md。失敗・検証不能は既存Skillを変更しない |
| 登録済みSkillだけのArtifact、背景と実行手順の分離 | Workflow節とSKILL_REVIEW.md。付随ノードを増やす許可にしない |
| 明示的な記憶依頼の例外と範囲、指定保存先 | Modes節。引用・tool出力・取り込みは新たな実行許可ではない |
| 未設定の既定値、auto=off、方針・設定が読めない場合 | Modes節。明示依頼の例外とPlan禁止を保持 |
| 同セッション・ターンのtoken、実モード確認、再帰禁止 | Stop節。承認設定名を実装モードの証拠にしない |
| 保存前の重複検索、検索失敗、追加情報のない更新禁止 | Persistence節。無関係な既存内容を保持 |
| 独立して保存価値があるノード間だけの型付きリンク | Persistence節。許可する5関係型と限界の保持を明記 |
| 全保存前の匿名化、私的データをhook状態へ残さない | Persistence節。意味が失われるなら保存しない |
| private／excluded／pendingの既定と独立した共有・学習許可 | Persistence節。自動承認は禁止、学習exportは承認済み構造化Caseのみ |
| export前の全文確認、指紋、変更時のレビュー失効 | Persistence節。画面やハッシュだけでプライバシーを証明しない |
| provenanceと参照データ扱い、保存後の読み戻し、ゼロ書き込み | Persistence節。保存しなかったこと自体をノートにしない |

## 実モデル比較

`gpt-6.1-sol`、推論設定`medium`、作業領域内だけ書き込み可能な子Codexで、合成資料を使った4ケースを変更前後各1回実行した。上限は各5分、計8回で再試行していない。内部思考の記録は採取せず、コマンド結果・成果物・終了時の使用量を確認した。

| ケース | 変更前後で一致した判断・確認 |
|---|---|
| 対象が一致 | 技術判断報告の冒頭に推奨と理由を置く指摘だけ採用。他の2候補は除外。成果物の順序・字数と`check`の成功を確認 |
| 対象が違う | 障害速報向けの指摘を初心者向け説明へ転用せず、全候補を除外。段落で操作を説明 |
| 今回の指示優先 | 過去の英語指定を除外し、今回の日本語指定と80〜120字を保持 |
| 保存判断 | 将来の明示的な好みは範囲・例外付きの保存候補とし、通常テストの通過・完了報告は除外。実際のノート保存は行わない |

検索・反映の3ケースは、変更前後とも採用・除外の記録と終了確認が成功した。保存判断ケースの変更前には追加の重複検索が失敗し、利用不能・重複未確認として報告された。候補の適格性と実際の保存許可を分ける判断は一致したが、このケースは実際の保存や検索経路の成功を証明しない。

最初の入力と、追加で読んだファイルを含むツール返却本文を同じトークナイザーで合算すると、4ケース合計で32,787から29,715へ約9.4％減った。参照先への単なる移動として扱わず、本文を読み直した分も含めた値である。繰り返し送信される会話履歴や出力はこの合算に含まない。

## 回帰検査とこのPCへの適用

全449件の回帰検査は、ブラウザー用ランタイム未指定の4件を除いて通過した。本文・適用範囲・警告を保つ表示処理、検索状態の区別、共通コマンド、直前版に対する文字数予算を追加検査した。既存のモード制限、根拠不足・改変の検出、一度だけの終了確認、更新時の設定保持、可搬版の実行経路も検査した。配布用818ファイルの生成一致、Bash構文、差分の空白検査を通過した。

検索・保存・構造検査・共有の各エンジンと、RECALL／CORRECTIONS／CAPTURE／AUDIT／SKILL_REVIEWの各ガイドは直前版から変更していない。このPCへ配置後、登録済みメモリーから候補3件の本文取得に成功した。個人ノートの内容ハッシュは不変で、イベントのpending件数は760件のままである。DB移行・イベント整理・commit・pushは行っていない。更新後のhook設定は新しいCodexセッションで利用する。

## 参考構成の確認

LISTBOXのAGENTS、README、docs/INDEXと、機能仕様・画面仕様・API仕様・データモデル・構成と開発運用・テスト仕様を実際に読みました。
短い開発ガイド、目的・セットアップ・コマンドを持つREADME、文書の内容を説明する索引、用途別仕様への相互参照を採用しています。
仕様書の対象範囲、実装から確認した条件、未確認事項を区別する構成も採用しています。
特定のフレームワークやPOST等をテストしないという固有制約は一般化していません。

読み取り専用の初期配置予定でも、既存の機能仕様・構成と開発運用・テスト仕様を再利用し、足りない目的・方針・コアロジックの文書だけを追加候補にすることを確認しました。
参考リポジトリ自体は変更していません。

## 文章生成の評価

`tools/repository-director/evals/run.py`は明示的な評価専用です。通常導入・自己テストからモデルを呼びません。
同じ架空の題材とCLI条件で、旧版と統合版のコミット・PR/MR・レビュー・引き渡しコメント・既存コードの文書案を生成します。
入力の事実、差分、確認結果と実際の本文を照合し、目的、具体的な変化、必要な条件、未確認、既存ルールの保持を確認します。
lintや文字列一致だけでは文章の品質を判定しません。実投稿、commit、pushは行いません。

2026-10-31に旧版と初期統合版を各1回生成し、6題材の本文を入力事実と照合しました。
両版とも目的・変更・確認結果・未確認を説明できました。統合版ではコミット本文の理由・検証範囲と、AGENTSから仕様・実装へ進む導線が追加されました。
一方、AGENTSの最上位見出しが二つになる問題は旧版と初期統合版の両方にありました。
既存の見出し階層へ統合し入口を短くする指示を加えて統合版を再生成し、5文書すべてで最上位見出しが一つになったことを確認しました。

[生成物・条件・読者としての確認](evidence/generation/review.md)に、旧版、修正前・修正後の統合版、入力、確認結果を残しています。
架空の入力にある「テスト成功」は説明の正確さを調べる素材であり、実アプリのテストを実行した結果ではありません。
文書案を一時領域へ配置して、リンクエラーなし、元のコード・テストのハッシュ不変、既存の接続禁止ルールの保持も確認しました。

この比較は全素材をプロンプトへ渡した文章提案の評価です。エージェントが実リポジトリを自律調査・編集するE2Eや、読み手の理解度を測る統計的評価ではありません。
同じCLI既定設定で実行しましたが、モデルIDは取得ログに公開されていません。一般的な品質向上や利用者満足を断定しません。

# 完成稿の読者視点レビュー

制作の会話を知らない読者として下書きを一度読む。素材、読者の知識、媒体、保護する事実に照らし、修正が必要な箇所だけを確認する。メモや自己採点を完成稿に出さない。短い連絡は必要な範囲だけ点検する。

1. 本文・見出し・図表・脚注に、会話への返答、制作報告、自己評価、申し出が混ざっていないか。正当なメールの依頼、研究目的、操作指示、引用は残す。
2. 段落冒頭を続けて読み、論旨と段落間のつながりを追えるか。各段落の論点に説明・根拠が対応しているか。
3. 重要な主張に「それは具体的にどういうことか」「なぜそうなるか」「実際には何が起きるか」「従来の方法と何が違うか」「その結果、何が可能になるか」という疑問が残るか。文章の目的に関係する疑問だけを扱い、全部へ答える型にしない。答えが既にあるなら追加しない。抽象語の言い換え、不要な例、毎段落の形式的な結論、接続詞や同じ構成の反復も確認する。
4. 素材と照合し、事実・数値・否定・主体・比較条件・因果・時系列・確信度が変わっていないか。新規執筆の仮想例や推論が実測と区別できるか。研究文書は対象、比較条件、結果、解釈、未検証事項を特に照合する。

重要な疑問が残り、資料に支えがある場合だけ必要な説明を補う。資料が足りなければ推測で完成させない。必要な条件は残し、過剰な免責や指示者向けの説明を再導入しない。問題がある箇所だけ最大一回改稿し、意味保持を確認する。問題がなければそのまま提出する。点数のために反復改稿しない。

機械検査は候補の発見と表記照合を担当する。抽象語や接続詞の数で理解可能性を判定せず、lintの0件も品質の証明にしない。文章品質の評価では具体性、因果の明瞭さ、読者理解、自然さ、情報効率、段落構造、意味保持、指示者向け表現を分ける。重大な事実変更や制作説明の混入を平均点で相殺しない。

上流更新は `--check-update` で確認し、更新後に `--doctor` と `--self-test` を行う。自己テストが測るのは導入と検査の挙動であり、文章品質は評価課題と実際のモデル出力で別に確認する。
